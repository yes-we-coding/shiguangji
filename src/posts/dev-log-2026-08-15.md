今天上午主要两条线：**博客自动化**的最后一公里、**配色**摇摆试错。一圈下来 commit 拉了 8 次，写一篇小结收束。

## 一、周报脚本又升级了

之前 `scripts/build-weekly-digest.mjs` 一直跑得挺稳，今天排查了一下，发现三个隐藏问题，一起修掉。

### 1. GitHub Trending 在某些网络下抓不到

`github.com/trending?since=weekly` 是 HTML 页面，在我这台机器上 `github.com` 走不到——TCP 包被丢又不返 RST，会一直挂到内核超时（分钟级）。

**修法**：加 **Search API 回退**。按 `pushed > 本周 + stars > 阈值` 排序，作为「最近活跃 + 高星」的近似榜单。HTML 解析成功就用 HTML，否则走 API，不影响原本在 GitHub Action 上的自动跑。

### 2. 框架版本取到了 monorepo 子包

之前用 `GET /repos/{repo}/releases/latest`，对 monorepo 不友好——GitHub 返回的是整个 repo 最新发布，不一定是 core 包。

两个真实案例：

- **Vite** → 显示 `plugin-legacy@8.2.3`（不是 vite core）
- **Astro** → 显示 `@astrojs/node@11.1.2`（不是 astro core）

**修法**：改走 **npm registry**。一次拿 `dist-tags.latest` + `time[version]`，版本和发布日期都拿到，结果还顺手发现：

- Vite 实际是 `8.2.1`
- Astro 实际是 `7.2.2`
- TypeScript 居然是 `7.0.2`（GitHub API 那个 `v6.0.3` 停在 4 月，明显 stale）

### 3. fetch 没超时，整个脚本会挂

配合第 1 点：没超时的 fetch 遇上丢包网络会等好几分钟才死。

**修法**：`fetchJSON` / `fetchText` 加 `AbortController` + **15s 默认超时**。单源失败不影响其它源（`safeRun` 仍然兜着）。

## 二、配色摇摆记

下午有一阵手痒，想换个配色看看。于是拉了个表挨个试：

| 版本 | commit | 第一眼感觉 |
|---|---|---|
| 🌿 鼠尾草绿（原版） | — | 自然清新 |
| ❄️ 冷雾灰 + 青绿 | `387fe30` | 像技术文档，缺博客气 |
| 🍊 焦糖橙 | `34baf0c` | 暖秋，但 link hover 橙得发慌 |
| 🟣 暮山紫 | `8bfa94a` | 优雅，但跟头像气质不太搭 |
| 🔵 雾霾蓝 | `a17f5ba` | 冷静文艺，整体偏"江南雨季" |

一圈下来：

- **冷雾灰 + 青绿**：上来就觉得太"产品文档"了，第一次就被否决（revert 1 次）
- **焦糖橙**：背景还行，落到交互色太跳
- **暮山紫**：漂亮但有点"装"
- **雾霾蓝**：是最接近能留下的一个，但还是偏冷

最终还是 **鼠尾草绿** 最耐看。`git log` 一翻，5 次 push + 1 次 revert 当健身了。

## 三、小结

写到这里三条心得：

1. **自动化是真有用**。周报草稿现在能稳定生成，Trending 不再被网络环境卡住——以后每周六 17:00 自己就能跑出来开 PR。
2. **配色还是原版最好**。博客这种东西，第一眼看顺眼的才是真的对。
3. **改色不能凭脑补，必须上 Pages 实际看**。5 个版本都是先 push 出去再回过头挑。
